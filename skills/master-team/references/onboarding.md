# 对话式分步教学

本文件在首次启用或用户要求学习/恢复教学时加载。教学由当前会话执行，不创建教学Worker，不向其他会话发欢迎消息。

## 进入条件与优先顺序

1. 审阅、编辑、打包技能或检查作者等维护请求：处理维护工作，不把开发者当新用户启动课程。
2. 用户明确说开始教学、继续教学、回到某步或重学：执行相应教学控制。明确暂停、跳过全部或关闭自动教学则立即尊重。
3. 已有团队或明确业务请求：直接沿用团队完成请求；如有必要用一句话解释当前步骤，不能以完成课程为前置条件。
4. 首次在用户请求中启用技能，或用户表示刚导入master-team，且没有暂停/关闭/已完成记录：主动给出第一步，不再追问“是否需要教学”。
5. 进度为in_progress且用户没有更优先任务：从current_step续接；completed、paused、dismissed或auto_start=false时不自动重讲。升级技能版本不重置已完成进度。

“导入后自动”指宿主发现并实际加载技能之后，在当前请求的会话中进入教学。文件复制不是会话事件，技能不能单靠文本在导入瞬间主动推送。宿主未加载时使用[first_use](../assets/first_use.md)的入口提示，不承诺一定自动选中技能。

## 交互节奏

- 使用用户当前语言，优先讲目标、动作和预期结果；Master解释为“协调者”，Worker解释为“执行成员”，再引入必要术语。
- 每次只推进一个需要用户参与的新步骤。默认控制在约200个中文字符，确需展示结果可适度增加，不一次输出整本教程、多个问题或大段字段。
- 每次最多问一个会影响下一步的关键问题，选项通常不超过3个。用宿主提供的提问方式，允许自由回答。已知平台、项目、目标和角色不重复问。
- 步骤所需信息已齐时可直接完成本步并说明下一步，不为了凑六轮人为提问；不靠空等“继续”拖住已授权工作。
- 用户说“继续”不代表同意创建成员、联系某个会话或发布。是否执行具体动作仍来自已有任务授权和宿主约束；普通可逆配置也不要重复索取已明确授予的授权。
- 首轮不展示schema、全部协议或整套安装目录；细节在用户需要时解释。不给尚未验证的能力、身份、学习结果或执行结果打勾。

## 六个步骤

| step_id | 本步目标 | 对话方式与完成条件 |
| --- | --- | --- |
| purpose | 让用户知道技能能帮什么 | 用两句话说明协调、执行与验收。若用途未知，只问希望先了解用法、配置项目还是接续团队；已知目标就概括并继续。 |
| environment | 确认当前环境 | 从宿主工具与当前目录识别平台、项目和成员。只问仍缺的一个关键信息；能力未验证就明确记未验证，不索要密钥。 |
| roles | 选合适的分工 | 结合用户目标推荐最少必要角色，解释每个角色负责什么。可选传统六角色；用户已选或项目已有配置时复用。 |
| setup | 把选择变成可用配置 | 区分只学习、写入本地配置和真正创建/联系成员。只学习给简短示例；配置按授权合并文件；实际建队另核宿主能力与已有授权。 |
| practice | 看懂一次派工和验收 | 默认只做带“模拟”标记的小例子，展示目标→执行回报→验收的关系。讲清done不等于验收通过；不运行发布或创建演练成员。 |
| first_task | 帮用户进入实际使用 | 用户有明确任务时直接进入原协作流程；尚无任务时只问第一个要完成的具体目标。教学完成可以记录，但真实任务执行/验收必须另记。 |

用户已掌握某步或信息明确时可以跳过该步，保留skipped_steps及简短原因。setup中的“了解配置”不等于已写入或已建队；practice完成不等于真实派单成功。

## 开场与后续话术样例

首次只有导入确认时：

> 我会分几步带你上手。Master负责分工和验收，Worker负责完成具体工作；你只需说明目标。第一步，你想先了解用法、配置一个项目，还是接续已有团队？

已有明确开发目标时：

> 你要完成的是这个功能，我会结合任务说明用法。当前先确认可用环境，再按需要安排实现和验证成员；已有的项目配置会直接沿用。

从暂停中恢复时：

> 上次停在选择分工，这次从这里继续。按你的目标，我建议先用实现和验证两个职责。你希望采用这个分工，还是使用已有成员？

样例用于展示语气，不逐字复读，也不在未核实进度或目标时假称“上次”做了什么。

## 暂停 跳步与恢复

- “暂停教学”：status=paused，保留current_step，不取消业务任务或停止Worker。
- “继续教学”：从当前未完成步骤续接；若有明确任务，允许边做边简短解释。
- “上一步”或“回到某步”：改变教学光标，重访已完成课程时把教学status置in_progress并保留已有步骤记录；不回滚项目文件、验收结果或已发生操作。
- “跳过这步”：记录skipped_steps，进入下一个未完成步骤；不代替尚未获得的行动授权。
- “直接开始任务”：停止阻挡业务的教学，status=dismissed；已有目标就执行，缺目标只问任务本身。
- “不再自动教学”：auto_start=false，可继续执行任务；仍允许用户以后明确重开教学。默认只影响本项目/学习者，不能擅改全局偏好。
- “从头再教”：重置教学进度，保留关闭自动教学的偏好，显式请求本身足够开启本轮；不重置团队登记、成员ID或工单。

## 进度保存

只保存[onboarding_state](../assets/onboarding_state.json)中的必要事实和步骤。默认位置是 `<TEAM_DIR>/onboarding_state.json`；若已知有其他学习者使用此项目，在 `<TEAM_DIR>/onboarding/<learner_scope>.json` 分开保存。learner_scope用用户认可的不敏感别名；无法确认是否同一学习者就只读旧状态并在当前会话记录，不覆盖他人进度。

模板永久保持空白；不用技能安装目录保存实际进度。只读教学或没有文件写入能力时，维护一行会话摘要即可，不为了落盘安装服务。首次保存只创建教学状态，不复制空团队登记表覆盖现有团队。

state必须匹配当前项目和学习者；不匹配时另建范围，不迁移旧用户的跳过/关闭偏好。不要保存密钥、凭据、对话全文或敏感业务细节。last_prompt_key只记步骤标识。更新进度不更改active_master_thread_id、generation或写占用。

教学状态损坏或范围尚未确认时，保留原文件并单独说明，不让修复教学进度成为执行明确业务任务或维护技能的前置条件。不要为继续业务静默重置用户的学习偏好。

completed_steps与skipped_steps互斥；只有六步都完成或明确跳过时才标completed。first_task步骤完成仅表示用户理解入口或已给目标，不代表业务任务完成。用户在中途退出不标课程完成。文件新版本号不触发重学。

课程已经completed时，“暂停”或“直接开始任务”维持已完成记录，不将finished光标写入paused/dismissed状态；关闭自动教学只改auto_start偏好。

可用[检查工具](../scripts/team_check.py)的onboarding子命令核进度并建议教学路线；它不理解自然语言、不发消息，也不改状态。真实对话的提问质量仍需在宿主中验证。
